## Coding Standards

**Type hints:**
- REQUIRED for all functions and methods
- Use `mypy` strict mode
- Import from `typing` or `typing_extensions` for Python 3.10 compatibility
- Use `if sys.version_info >= (3, 11): from typing import Self else: from typing_extensions import Self` pattern

**attrs classes:**
- Use `@define` decorator (not `@dataclass`)
- Use `field(factory=...)` for mutable defaults
- Use `field(converter=...)` for automatic type conversion
- Example: `security_context_flags: SecurityContextFlags = field(default=SecurityContextFlags(0), converter=SecurityContextFlags)`

**Naming conventions:**
- Classes: `PascalCase` (e.g., `BlockConfidentialityBlock`)
- Functions/methods: `snake_case` (e.g., `update_crc`)
- Constants: `UPPER_SNAKE_CASE` (e.g., `DTN_EPOCH`, `BLOCKFUNCTIONS`)
- Private: prefix with `_` (e.g., `_structure`, `_unstructure`)

**File organization:**
- Source: `src/bespokebpv7/`
- Tests: `tests/` (not nested, flat structure)
- Test file naming: `test_<module>.py` (e.g., `test_bcb.py` for testing `bpsec.py` BCB class)

**Import style:**
- Use `# type: ignore[import-untyped]` for imports from bespokebpv7 (package not typed for external use)
- Group imports: stdlib, third-party, local
- Avoid star imports

## Testing Requirements

**Test structure:**
- Property-based tests with Hypothesis for data structures, serialization, flag operations
- Custom strategies in `tests/strategies.py` using `st.builds()` pattern
- Roundtrip tests: `create → bundle_converter.unstructure() → bundle_converter.structure() → verify`
- Mix static identity assertions with generated data

**Coverage:**
- Target: 95% branch coverage minimum
- Run: `tox -e clean && tox -e 3.10 -e 3.11 -e 3.12 -e 3.13 -e 3.14 && tox -e coverage`
- View: `htmlcov/index.html`

**Test patterns:**
- Identity values (block_type, security_context_id) remain static assertions
- Variable data (keys, flags, targets) generated by Hypothesis
- Test BOTH RFC-compliant AND intentionally non-compliant cases
- EID normalization: test with `"dtn:0"` and verify `"dtn:none"` result

**Hypothesis:**
- Default 100 examples per test
- Only use `@settings(deadline=None)` if tests timeout (>10 seconds)
- Strategies for common types already exist in `strategies.py`: `st_eid`, `st_data`, `st_creb_params`
- Create new strategies for reusable components
- Use inline `st.*` for test-specific generation

**Property assertions (NEW tests should include):**
- Idempotence: `set_flag(X); set_flag(X)` = `set_flag(X)`
- Inverse: `set_flag(X); clear_flag(X)` results in cleared
- Independence: Setting one flag doesn't affect others
- Roundtrip stability: `structure(unstructure(obj))` preserves all fields
- Conditional structure: `parm_present == True` ⟺ `len(security_parameters) > 0`

## CRC Handling

**CRITICAL**: CRCs are MANUAL. Never forget:
1. Modify block → 2. Call `block.update_crc()` → 3. Serialize

**Common mistake:** Forgetting to update CRC after modification leads to CRC mismatch warnings on parse.

**Test pattern:**
```python
bcb.add_security_result(b"tag")  # Modification
bcb.update_crc()  # REQUIRED before serialization
bytes(bcb)  # Now CRC is correct
```

## Review Criteria

**Before code review passes:**
- [ ] JPL header present and Modified date current
- [ ] All functions have type hints
- [ ] `mypy --strict` passes
- [ ] `ruff check --fix` applied
- [ ] Extension blocks registered in BLOCKFUNCTIONS
- [ ] Admin records registered in ADMINFUNCTIONS
- [ ] CRC updated after all block modifications
- [ ] Tests include property-based checks (not just static examples)
- [ ] Coverage ≥95% branch coverage
- [ ] Tests pass: `tox` (all Python 3.10-3.14)
- [ ] EID normalization handled correctly

**Failure modes to check:**
- CBOR decode errors handled (no bare `cbor2.loads()` without try/except)
- CRC mismatches emit warnings (not silent failures)
- Invalid block types gracefully fall back to `CanonicalBlock`
